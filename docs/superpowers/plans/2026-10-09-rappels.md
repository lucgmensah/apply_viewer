# Rappels et notifications — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Poser un rappel (date + heure) sur une candidature et recevoir une notification du navigateur à l'heure prévue.

**Architecture :**
- Des fonctions pures dans `shared.js` calculent les rappels (échus, prochain, raccourcis, report).
- `background.js` les charge via `importScripts` et programme une alarme unique `next-reminder`, recalculée à chaque modification des candidatures et à chaque démarrage. Quand elle sonne, il crée les notifications et gère leurs actions.
- `ui.js` fournit le composant « Rappel », utilisé par le dashboard, la popup et le widget.

**Tech Stack :** Chrome MV3 (`chrome.alarms`, `chrome.notifications`), vanilla JS, `node:test`, Puppeteer.

**Spec :** `docs/superpowers/specs/2026-10-09-rappels-design.md`

## Global Constraints

- Format stocké : `reminderAt` = `AAAA-MM-JJTHH:mm` (heure locale) ou `''`. Un champ absent équivaut à `''`.
- Heure des raccourcis : 9 h 00 locale. Raccourcis : J+1, J+3, J+7.
- Nom de l'alarme : `next-reminder`. Id de notification : `reminder:<id>:<reminderAt>`.
- Titres des notifications :

  | Statut | Titre |
  |---|---|
  | `wishlist` | « Postuler : » |
  | `applied` | « Relancer : » |
  | `interview` | « Entretien : » |
  | `offer` | « Offre : » |
  | `rejected` | « Rappel : » |

  Le titre est suivi du poste ; le message est « Entreprise · Lieu ».
- Boutons : « Ouvrir l'offre » (seulement si l'URL est `http(s)://`), puis « Reporter à demain ».
- Libellés de l'interface :
  - pastilles : « Demain 9 h », « Dans 3 jours », « Dans 1 semaine », « Retirer » ;
  - messages : « Choisissez une date à venir », « Rappel programmé », « Rappel retiré » ;
  - liste d'ajout : « Me rappeler », avec « Pas de rappel » par défaut.
- Aucune dépendance runtime ni étape de build ; toute écriture passe par `JobTracker.update`.

## Review Focus

1. **Heure d'été / changement d'heure** : un rappel à 09:00 reste à 09:00 locale après un changement d'heure, car les calculs se font en dates locales et non en ajoutant 24 h. → Test unitaire `snoozeValue` et `reminderPresets` sur la nuit du changement d'heure (tâche 1).
2. **Rappel modifié pendant la notification** : le retrait de `reminderAt` ne s'applique que si la valeur est inchangée. → Test de bout en bout (tâche 2).
3. **Valeur `reminderAt` invalide dans les données** : ignorée, sans erreur dans le service worker ni dans l'interface. → Tests unitaires (tâche 1) et de bout en bout (tâche 2).
4. **Titre contenant du HTML** : affiché comme du texte dans le tag de la carte et dans la notification. → Tâche 3, et l'API de notification n'interprète pas le HTML.
5. **Navigateur fermé à l'heure prévue** : notification à la planification suivante. → Tâche 2, avec un rappel déjà échu dans les données.

### Task 1 : Fonctions de rappel dans `shared.js`, `globalThis`

**Files :**
- Modify : `shared.js`, `ui.js` (`window` → `globalThis`)
- Create : `tests/unit/reminders.test.js`

**Interfaces — Produces (`JobTracker.*`) :**

| Fonction | Contrat |
|---|---|
| `parseReminder(value: string): Date \| null` | Date locale ; `null` si la valeur est vide, mal formée ou hors limites. |
| `toReminderValue(date: Date): string` | Date → `AAAA-MM-JJTHH:mm`. |
| `reminderPresets(now: Date): { tomorrow: string, in3days: string, in1week: string }` | Raccourcis à 9 h 00 locale. |
| `dueReminders(list, now: Date): Candidature[]` | Candidatures dont le rappel est ≤ `now`. |
| `nextReminderTime(list, now: Date): number \| null` | Horodatage du plus proche rappel > `now`. |
| `snoozeValue(reminderAt: string, now: Date): string` | Date de `now` + 1 jour, à l'heure de `reminderAt`. |

- [ ] **Step 1 :** écrire les tests :
  - `parseReminder('2026-10-10T09:00')` donne le 10/10/2026 à 9 h 00 ;
  - `''`, `'abc'` et `'2026-13-45T09:00'` donnent `null` ;
  - `toReminderValue(new Date(2026, 0, 5, 7, 3))` donne `'2026-01-05T07:03'` ;
  - `reminderPresets(new Date(2026, 9, 9, 22, 0))` donne `{ tomorrow: '2026-10-10T09:00', in3days: '2026-10-12T09:00', in1week: '2026-10-16T09:00' }` ;
  - autour du changement d'heure, `reminderPresets(new Date(2026, 9, 24, 12))`, la valeur `tomorrow` vaut `'2026-10-25T09:00'` ;
  - `dueReminders` ignore les rappels vides ou invalides et inclut un rappel égal à `now` ;
  - `nextReminderTime` renvoie le minimum strictement supérieur à `now`, ou `null` ;
  - `snoozeValue('2026-10-09T14:30', new Date(2026, 9, 9, 15))` donne `'2026-10-10T14:30'`.
- [ ] **Step 2 :** `npm test` → FAIL (fonctions absentes).
- [ ] **Step 3 :** implémenter. Remplacer `window.` par `globalThis.` dans `shared.js` et `ui.js`.
- [ ] **Step 4 :** `npm test` → PASS, puis `npm run e2e` → PASS (aucune régression).

- [ ] **Step 1 : tests de bout en bout** (le worker est lu via `harness.worker`) :

  - un rappel déjà échu dans les données (`seed`) est notifié immédiatement ;
  - `reminderAt: 'invalide'` : pas de notification, pas d'erreur dans le worker ;

  - sans URL, le bouton 0 est « Reporter » ;
  - `reminderTitle` donne « Relancer : Dev » pour une candidature `applied` ;
  - modification pendant la notification : le rappel est changé entre la création de la notification et l'écriture → la nouvelle valeur est conservée. On teste la fonction de retrait `clearFiredReminders(list, fired)`, exposée, avec une liste où la valeur diffère.
